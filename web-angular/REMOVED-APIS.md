# Removed APIs — dummy / static frontend

As we convert the member portal to a backend-free dummy environment, this tracks
every API we stop calling, flow by flow. Each row: the API, what it did in plain
words, the screen it powered, and what replaced it.

| # | API (method + path) | What it did | Screen / flow | Replaced with |
|---|---------------------|-------------|---------------|---------------|
| 1 | `GET /api/policies/{policyId}/current` | Fetched the member-readable policy — number, corporate, validity, and the covered / not-covered lists — from the plan config. | Policy details page (`/member/policy-details/:id`) | Static data in `core/member/static-policy.data.ts` (served via `PolicyStore`). Enriched with sum insured, co-payment, members covered and claim window. |
| 2 | `GET /api/wallet/balance?userId=` *(entire home use)* | Supplied both the home "Total Available Balance" card and the per-category "Health Benefits" cards. | Home page — wallet total + Health Benefits grid | Static in `static-policy.data.ts`: `STATIC_WALLET_TOTAL` (₹40,000 benefit wallet, shown full) and `STATIC_BENEFITS` — 9 fixed benefits (Online/In-Clinic Consultation, Vision, Dental, Pharmacy, Vaccination, Pathology, Radiology & Cardiology, Annual Health Check), each ₹5,000 annual · ₹500 per-claim · ₹400 per-service. `wallet/balance` is no longer called on the home page (still used by the Wallet screen). |

| 3 | Bookings aggregate: `GET appointments/user/:id`, service-booking, lab, `GET ahc/orders`, `GET pharmacy/orders`, plus `PATCH/PUT/POST …/cancel`, invoice download, cancel-prescription, and `POST vaccination/:ref/demo-advance` | Loaded and managed the member's bookings across consultations, dental, vision, lab, AHC, pharmacy and vaccination. | Bookings screen (`/member/bookings`) | Store rewritten to serve `STATIC_BOOKINGS` (in `core/bookings/static-bookings.data.ts`) with no HTTP; cancel / invoice / prescription / demo-advance actions are inert. Kept **empty** — the dummy wallet is full and undeducted, so there are no spends to show; the screen renders its empty state. |

| 4 | Annual Health Check APIs: `GET member/ahc/eligibility`, `member/ahc/package`, `member/ahc/orders`, `member/ahc/vendors/lab`, `member/ahc/vendors/diagnostic`, `member/ahc/orders/:id`, `…/diagnostic` (add leg), `member/ahc/demo-reset`, `member/ahc/reports/*` | Eligibility, package, vendor lists, slot/order creation and reports for the annual health check. | Wellness / AHC flow (`/member/wellness`) | `wellness-page.ts` rewritten as a **self-contained static wizard** (no API): three entry options, Route A (pathology → radiology) and Route B (full package), per-leg steps (postal → mode → provider → address/centre → slot → review → confirmed & billed), grey-out rules, once-a-year limit, a demo reset, and a post-booking order-status tracker (spec steps 13–15: order confirmed → sample collection / scan → report delivered to Health Records) that demo-advances through the states. The old AHC sub-pages/stores are left orphaned (not reached from the journey). |

| 5 | Online consultation APIs: specialties, doctor availability/list, select-patient, slots, payment breakdown, wallet block + Razorpay, booking create, invoice, consultation session (Agora/Daily), e-prescription | The whole online video/audio consultation journey. | Online Consultation (`/member/online-consult`) | New self-contained static wizard `features/online-consult/online-consult-page.ts` (no API): Consult Now / Schedule → speciality → doctor list (search + empanelment request) → patient → video/audio → slot (scheduled only) → payment breakdown (wallet block + Razorpay self-pay) → booking confirmed → invoice → in-app consultation → e-prescription → Health Records. Cancellation shown but not allowed (per spec). Route pulled out of the shared appointments flow; in-clinic appointments untouched. |

| 6 | In-clinic consultation APIs: specialties, geolocation/places (Google Maps), doctor-by-distance list, select-patient, slots, appointment create (pending confirmation), backend confirmation, cart/payment breakdown, wallet block + Razorpay, receipt, cashless letter, prescription upload, complete/invoice | The whole in-clinic physical consultation journey. | In-Clinic Consultation (`/member/appointments`, and the `/specialties` deep link) | New self-contained static wizard `features/appointments/inclinic-page.ts` (no API): Book New Consult → speciality → detect location / postal code → doctors by distance (search + empanelment) → patient → slot (today+36h) → request raised & pending confirmation (wallet blocked, no payment) → simulate clinic confirmation → cart ready → payment breakdown (wallet block + Razorpay) → receipt → cashless letter → visit → upload prescription → completed & invoice. Old shared appointments sub-pages (consult-hub, specialties, doctors, confirm) orphaned. |

| 7 | Vision APIs: coverage/eligibility, partner (Lenskart) list, prescription upload, order create + coupon issue, order/cart status | The member's half of the vision journey. | Vision (`/member/vision`) | New self-contained static wizard `features/vision/vision-page.ts` (no API, no wallet block): policy coverage → Start New Order → pick partner + mode (online/in-store) → upload prescription → submit → coupon code + partner link → (partner pushes the cart back) cart with selected items → payment breakdown (wallet-covered vs out-of-pocket, Razorpay) → paid & settled. No wallet block at booking — charged only after the partner reports the cart. `/member/vision` no longer uses `BenefitServicesPage`. |

| 8 | Pharmacy APIs: prescription upload / existing list, digitisation queue, adjudicator cart build (Tata 1mg), cart push, wallet block/recalc, checkout payment (wallet + Razorpay), order create, receipt, delivery, invoice, refund | The whole prescription-led pharmacy journey. | Pharmacy (`/member/pharmacy`) | New self-contained static wizard `features/pharmacy/pharmacy-page.ts` (no API): upload / pick prescription → queued for digitisation → simulate adjudicator building & pushing the cart → cart the member can only reduce (delete / decrement, never add; substitutes marked with original brand; wallet block recalculates) → checkout breakdown (wallet + copay + Razorpay) → order placed → receipt (delivery + invoice-after-delivery noted). Old `features/misc/pharmacy-page` orphaned. |

| 9 | Dental APIs: dentist compare/list, slots, appointment create (pending), backend confirmation, cart/payment, wallet block + Razorpay, receipt, cashless letter, prescription upload; procedure route: estimate, cart-on-hold adjudication, approved cart, procedure slot/payment/confirmation/invoice | The whole dental consultation + optional procedure journey. | Dental (`/member/dental`) | New self-contained static wizard `features/dental/dental-page.ts` (no API): compare dentists → book (slot + patient + contact) → pending confirmation (wallet blocked) → simulate confirm → cart + payment (wallet + Razorpay) → receipt + cashless (2h prior) → visit → upload prescription + "procedure recommended? Y/N". **No** → completed. **Yes** → add estimate → create cart on hold → simulate adjudication → approved cart → slot with same dentist → payment → receipt + pending → simulate confirm → cashless → procedure completed + invoice. `/member/dental` no longer uses `BenefitServicesPage`. |

| 10 | Vaccination APIs: vaccine catalogue (age/gender eligibility), vendor list, optional prescription upload, slots, appointment create (pending), backend confirmation, cart/payment, wallet block + Razorpay, receipt, cashless letter, vendor completion/no-show, invoice | The whole vendor vaccine booking journey. | Vaccination (`/member/vaccination`) | New self-contained static wizard `features/vaccination/vaccination-page.ts` (no API): select vaccine + dose → patient + optional prescription → provider + slot → pending confirmation (wallet blocked) → simulate vendor confirm → cart + payment (wallet + Razorpay) → receipt + cashless (2h prior) → visit → simulate vendor outcome (dose administered / no-show) → completed + invoice (or no-show). Old `vaccination-services-page` orphaned. |

| 11 | Pathology / Radiology & Cardiology APIs: test catalogue (concern tabs), provider list/pricing, serviceability, slots, order create (on hold), backend adjudication (remove/reprice), cart/payment, wallet block + Razorpay, receipt, provider confirm, collection/scan status, report, invoice, refund | The whole diagnostics journey (both cards). | Pathology (`/member/lab-tests`) + Radiology (`/member/diagnostics`) | One self-contained static wizard `features/diagnostics/diagnostics-page.ts` (`kind` bound from route): concern tabs → select test/package → provider → mode (pathology only) + slot → order on hold → simulate adjudication (drops a duplicate test) → adjusted order + payment breakdown (test value + collection charge, wallet + Razorpay) → receipt → order-status tracker (confirmed → collection/scan → report) → invoice after delivery. Old `features/lab/lab-tests-page` and `features/lab/diagnostics-page` orphaned. |

| 12 | `GET wallet/balance`, `GET wallet/transactions` (wallet screen's use) | Powered the Wallet screen's totals, per-category balances and the transaction ledger. | Wallet (`/member/wallet`) | Redesigned static `features/wallet/wallet-page.ts` (no API): gradient hero (available/allocated/used with progress), 3 stat tiles, per-benefit cards with mini progress bars (from `STATIC_BENEFITS`), and an empty "Recent activity" state. Old `wallet-ledger` orphaned; `wallet/balance` no longer called anywhere in the member portal. |

| 13 | All claims APIs: `member/claims` (list), `member/claims/summary`, `member/claims/available-categories`, `POST member/claims` (create), `POST …/submit`, `PATCH …/cancel`, `GET …/{id}`, `…/timeline`, `…/tpa-notes`, `POST …/resubmit-documents`, `member/claims/files/*` | The whole reimbursement claim flow. | Claims (`/member/claims`, `/new`, `/:id`) | `ClaimsStore` rewritten static (`core/claims/static-claims.data.ts`): seeded list across statuses, in-memory submit/cancel/resubmit, static categories (with copay + limits), static timeline/notes. new-claim decoupled from `WalletStore` (static ₹5,000 category balance). | 14 | `member/addresses` (GET/POST), `notifications` + `notifications/unread-count` + mark-read, digital-prescriptions / prescriptions, `transactions` + `payments` | Profile addresses, the notifications list + header bell badge, Health Records (prescriptions), and the Transactions history + detail. | Profile, Notifications, Health Records, Transactions | The four stores (`profile.store`, `notifications.store`, `records.store`, `transactions.store`) rewritten static (seeded in-memory data; save/markRead/setFilter mutate locally). The header bell badge now derives from the static notifications. No `member/addresses`, `notifications*`, `prescriptions`, or `transactions`/`payments` calls remain. |

## Notes

- **Policy card (home "Your Policies")** — no dedicated API of its own; it was
  derived from the `member/profile` assignments. It is now served from
  `STATIC_POLICIES` in `static-policy.data.ts`. `member/profile` itself is still
  called (it powers family / wallet), so it is **not** listed as removed — only
  the policy card's dependence on it was cut.
